# Product Requirements Document (PRD): edgar-pipeline

> Data pipeline for SEC EDGAR filings: Dagster orchestration, dbt models on DuckDB, MLflow experiments; feeds fredgar-ai and law-ai.

Open work is tracked in [GitHub Issues](https://github.com/bamr87/edgar-pipeline/issues) and as `status: planned` entries in [features/features.yml](features/features.yml).

## 1. Overview

A modern data stack in miniature: ingest EDGAR filings, model them with dbt on DuckDB, orchestrate with Dagster, and track ML experiments in MLflow.

| Version | Date | Notes |
| --- | --- | --- |
| 0.1 | 2026-10-28 | Initial requirements and phased roadmap (repo foundation). |

## 2. Goals

- Incremental EDGAR ingestion respecting SEC fair-access rules
- dbt models for companies, filings and XBRL facts on DuckDB
- MLflow-tracked models whose outputs feed fredgar-ai and law-ai

Non-goals (near term): production hosting, paid services, anything outside the roadmap below without a PRD change.

## 3. Users

- The maintainer, learning data orchestration with dagster assets, dbt modeling and tests by building.
- Fleet agents (hub evolution loop, backlog fan-out, `evolve` lane) that grow the repo one reviewed PR at a time.
- Fleet tie-in: Upstream data source for bamr87/fredgar-ai (financial facts) and bamr87/law-ai (filing text).

## 4. Requirements

Phases are the build order: an agent picks the earliest unserved requirement first.

### 4.1 Phase 1 — Foundation

- FR1: Python package with an EDGAR User-Agent config and tests
- FR2: Fetch company submissions JSON with rate limiting (10 req/s cap)

### 4.2 Phase 2 — Core

- FR3: Dagster assets for raw submissions and company facts
- FR4: dbt project on DuckDB with staging and mart models

### 4.3 Phase 3 — Fleet integration

- FR5: MLflow-tracked baseline model on filing features
- FR6: Export marts consumed by fredgar-ai and law-ai

### 4.4 Non-functional

- NFR1: CI (`.github/workflows/ci.yml`, the fleet standard gate) passes on every PR.
- NFR2: No secrets or credentials are committed; configuration comes from environment variables.
- NFR3: Autonomous lanes are off by default, open pull requests only, and never merge.
